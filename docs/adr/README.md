# Architecture decision records

Status: APPROVED | Updated: 2026-10-04 (Asia/Jakarta) | Custodian: Planning Agent

This folder owns future ADRs. **No architecture design or accepted ADR exists in P0.** The Owner's preferred stack is recorded in [DECISION_LOG](../00-governance/DECISION_LOG.md) and [TOOLCHAIN](../00-governance/TOOLCHAIN.md), rather than fabricated as a completed P4 decision.

Create a stable ADR only inside authorized scope for a material stack, architecture, integration-boundary, schema, security or deployment decision. Include ID/title, DRAFT/PROPOSED/ACCEPTED/REJECTED/SUPERSEDED status, date/custodian, context and evidence, alternatives, decision and rationale (including any rejection reason), risk, cost, compatibility/data impact, migration/rollback implications, affected decisions/docs/phases/Tasks, approval requirement and actual approval reference.

Material deviations from the preferred stack or approved architecture require ADR plus explicit Owner approval under [CHANGE_CONTROL](../00-governance/CHANGE_CONTROL.md). A proposed ADR is not implementation authorization. Preserve accepted records and link supersession; update DECISION_INDEX, owning docs, phase status and handoff after actual approval. Do not create Task contracts here.
